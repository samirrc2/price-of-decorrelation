# The Price of De-correlation

Code and reproducibility pipeline for a pre-registered study of **model heterogeneity
in multi-agent LLM ensembles**: how much cross-provider heterogeneity de-correlates a
five-agent committee's directional calls (Fleiss' κ), what inference-cost premium that
buys, and whether the de-correlation translates into any downstream benefit.

The confirmatory study runs **54,000 independent LLM calls** across three five-agent
configurations spanning heterogeneity levels {0, 1, 3}, over 100 equities × 12 dates ×
3 runs, cross-provider (OpenAI / Google / xAI).

**Headline results** (regenerated by the pipeline, not committed):

- Primary de-correlation: **Δκ(HOM−HET) = 0.336**, 95% CI [0.304, 0.369] — *Confirmed*.
- Agreement–cost frontier: a **~4.4× inference-cost premium** buys the de-correlation.
- Capability-matched control: **Δκ = 0.315** [0.288, 0.341] (~94% of the effect) — the
  de-correlation is provider-driven, not a capability-tier artifact.
- Temperature robustness: the ordering and the primary contrast hold at T ∈ {0.0, 0.7, 1.0}.
- Consensus structure (exploratory): homogeneous ensembles produce confident, unanimous,
  *wrong* directional calls at ~1.8× the heterogeneous rate.

> This repository contains **code and seed data only**. The manuscript (LaTeX/PDF) and
> its build tooling are intentionally excluded; every result file is regenerated from
> `runs.csv` by the analysis code below.

## Reproduce

All commands are run from the repository root.

```bash
pip install -r requirements.txt

# API keys live in the sibling "API Keys" folder (env vars override):
#   ../API Keys/keys.env   with OPENAI_API_KEY, GEMINI_API_KEY, XAI_API_KEY, FMP_API_KEY
python src/secrets.py                 # sanity: which providers have keys (prints no secrets)

python src/fetch_prices.py            # cache EOD prices  (network; one-time)
python src/build_data.py              # build no-lookahead snippets + forward returns
python src/orchestrator.py --dry-run  # validate config + grid + project worst-case cost
python src/orchestrator.py            # run / resume the 54k-call grid (spend-capped)
python src/analyze.py                 # figures, tables, metrics_summary.md, verdict
```

Offline dry test (no keys, no spend): `PILOT_MOCK=1 python src/orchestrator.py` runs the
full grid against a deterministic offline stand-in. Clear `cache/ results/ runs.csv`
afterward before a real run.

Robustness studies (kept fully separate from the frozen `runs.csv`):

```bash
# Capability-matched control
python src/orchestrator.py --config configs/config_control.yaml --phase full
python src/control_kappa.py

# Temperature sensitivity (writes temp_sweep/, ~2,160 calls, ~$2-4)
bash scripts/run_temp_sweep.sh

# Consensus-structure / tail-risk re-analysis (frozen data only, no API calls)
python src/reviewer_analysis.py
```

## Design guarantees

- **Independent-draw estimand.** Each agent gets a unique, reproducible seed
  `SHA-256(master, run, config, ticker, date, agent) & 0x7FFFFFFF`, so a homogeneous
  ensemble is five *independent* draws of one model, not one draw copied five times.
  (The pilot's per-run seed sharing inflated Δκ from 0.113 to 0.485 — see the paper's
  measurement-protocol section and `archive/pilot_v1/`.)
- **No lookahead.** Every snippet's `asof` date is asserted strictly before the analysis
  date; context is price-derived from public prices only.
- **Deterministic & resumable.** Fixed seeds; completed rows in `runs.csv` are skipped so
  a killed run resumes exactly. `analyze.py` is a pure function of (`runs.csv`, config).
- **Spend cap & rate limits.** The orchestrator projects each call's worst-case cost and
  stops before the cap; per-provider RPM limiters and a daily-quota circuit breaker keep
  the run under provider limits.
- **Full provenance.** Each call logs model, seed, prompt hash, timestamp, tokens, cost,
  and raw response.

## Notes

- `knowledge_cutoff` and pricing in `configs/config.yaml` are **placeholders to verify**
  against current provider documentation — they cannot be confirmed from inside the code.
- `secrets.py` never prints key material; it reports only which providers are configured.
